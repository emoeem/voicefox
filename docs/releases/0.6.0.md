# VoiceFox 0.6.0

## 版本概览

这一版的主角是 **QQ 音乐支持微信账号登录**（[issue #43](https://github.com/emoeem/voicefox/issues/43)）：
改动只落在 QQ 音乐这一条音源上 —— 多出「渠道」概念，界面里 QQ 音乐从一行变成
**`QQ` / `QQ（微信）`两个入口**，微信注册的账号终于能扫码登录。
版本号走到 **0.6.0**（新增用户可见功能）。

此外还有三组改动：**频谱可视化的三个毛病**（封面图形留下的矩形黑块、
采集源选错、没有声音时画面像卡死）、**Scoop 清单自动刷新**，
以及 **CI 增加 fmt + clippy 零警告门禁**（顺带把代码清理过一遍）。

---

## 一、QQ 音乐支持微信账号登录（新，issue #43）

在此之前 QQ 音乐源只有 QQ 扫码一条路，微信注册的 QQ 音乐账号扫不出结果 ——
两条链路在服务端是**完全不同的协议**，不是换个参数的事
（`ptqrshow` 加 `login_type=2` / `appid` / `ptlang` 全部被忽略，照发 QQ 二维码；
`ptqrlogin` 没有合法 `qrsig` 直接 403）。

- **渠道进入能力层**：新增 `QrLoginKind::{Standard, WeChat}` 与
  `QrLoginSession.kind`（`#[serde(default)]`，旧数据照常反序列化）；
  `SourceCapabilities.wechat_login` 声明「这个音源额外有微信入口」，
  `MusicSource::create_qr_login_kind` 带默认实现转调原有 `create_qr_login`，
  所以网易云 / 哔哩哔哩 / 酷狗**零改动**。
- **界面**：设置页「账号与扫码」里 QQ 音乐占两行，标题分别是 `QQ` 与 `QQ（微信）`；
  扫码浮层标题带「微信」角标；二维码过期自动重建时沿用同一条渠道。
- **微信链路**（复用 QQ 音乐自己网页版登录走的那条，不是私有协议）：

  1. `open.weixin.qq.com/connect/qrconnect` 用 appid `wx48db31d50e334801`
     （QQ 音乐在微信开放平台的网站应用）取二维码页面 → 抽出 uuid；
  2. `open.weixin.qq.com/connect/qrcode/{uuid}` 取二维码**图片**；
     长轮询 `lp.open.weixin.qq.com/connect/l/qrconnect`（服务端约 15s 返回一次，
     该请求单独放宽到 35s 超时；首见 404 之后每轮都回带 `&last=404`）；
  3. `music.login.LoginServer/Login`（`tmeLoginType="1"` + `strAppid` + `code`）
     换回 `musickey`；
  4. 落成 cookie 复用整条既有登录态链路：`uin` / `wxuin` 记身份，
     `qqmusic_key` / `qm_keyst` 记音乐凭证，另存 `wxopenid` / `wxunionid` /
     `wxrefresh_token` / `wxaccess_token` 供续期。

- **登录判定放宽**：从「`uin` + `qqmusic_key` 都在」改成
  「身份（`uin` / `wxuin`）与音乐凭证（`qqmusic_key` / `qm_keyst`）**各命中一个**」，
  微信账号与历史登录数据都能识别。
- **二维码图片而非链接**：微信这条给的是 JPEG 字节，走 `image_png`（base64）渲染；
  `url` 刻意留空 —— 微信二维码的内容是 `connect/confirm?uuid=…`，
  用文本重编码会扫出一张无效码。
- **只读探针**：`cargo run -p lx-source --example wechat_probe`
  把二维码写到系统临时目录（`$TMPDIR`，Linux 上通常是 `/tmp`）的
  `voicefox-wechat-qr.jpg`、打印每一轮轮询状态；
  真扫成功后原样打印 `req.data` 且**不落盘**，用来确认字段再谈后续。
  自动化能验到「生成二维码 → 轮询 Waiting」，**真人扫码之后的字段仍未验证**。
- **调研与证据**：`docs/research/qq-music-wechat-login.md` 记了第一方证据
  （`wx_redirect.html` 内联 JS 与实测逐字一致）、11 条实测记录、
  3 个第三方库佐证，以及尚未验证的清单（VIP / 无损能否解锁等）。
- **兜底仍在**：设置页「手动粘贴 Cookie」入口不受影响，从浏览器复制
  `uin` / `qqmusic_key` / `login_type=2` 即可，与扫码共用同一套落盘逻辑。

## 二、频谱可视化：修掉封面留下的矩形黑块

按 `w` 开频谱后，内容区左上会留一块矩形（位置恰好是封面图片区），
底色和频谱舞台不一样。原因是**叠加层每帧重绘时没有清 `CellDiffOption`**：

封面走终端图形协议（kitty / iTerm2 / sixel）时，图片区域每行第一格被塞进
整行转义序列，其余格子被标成 `Skip`（禁止参与差分输出）；而 ratatui 的
`set_char` / `set_fg` / `set_bg` / `set_style` **都不会清 `diff_option`**，
只有 `reset()` 或显式 `set_diff_option` 会。频谱的 `paint_cell` / `paint_background`
正好只调前几个 setter，于是封面图片区被永久排除在差分之外，终端保持旧画面 ——
按 `w` 后那里首列的图转义被覆盖、kitty 撤掉 placement，露出的就是旧底色。

- `paint_cell` / `paint_background` 收尾显式 `set_diff_option(CellDiffOption::None)`。
- **关闭**频谱时改为重传封面（`retransmit_cover`）：开启期间每帧都会覆盖
  封面图片行首那格，不重传的话关掉频谱后封面区域会空着。
- 回归测试 `spectrum_clears_diff_markers_left_by_cover_graphics`：
  先照图形协议的做法把区域标成 `Skip` / `ForcedWidth`，再断言频谱渲染后
  每格 `diff_option` 都回到 `None` —— **不打补丁这条测试会失败**。
- 对照：模态浮层走 `Clear`（内部是 `cell.reset()`），本来就没有这个问题。

## 三、频谱：采集源选错、断流看不见、静默时像卡死

- **采集源锚定**：优先 `parec -d @DEFAULT_MONITOR@`；`pw-record` 只在
  `pactl get-default-sink` 查得到真实 sink 时兜底 ——
  `pw-record --target @DEFAULT_MONITOR@` 会被 PipeWire **静默忽略并退回默认麦克风**，
  结果是「频谱在动，但画的是自己说话」。开机自启（PipeWire 尚未就绪）时
  还会重试而不是直接放弃。
- **断流看得见**：采集子进程的 stderr 由专属线程持续读走（只保留末尾
  1024 字节用于报错 —— 不读走的话子进程写满管道就会卡死），
  退出时按信号 / 退出码给出可读原因。
- **自动恢复**：重连按 0.5s → 1s → 2s → 4s 指数退避、封顶 5s。
- **静默不再像卡死**：新增静默监测线程 —— 1.5s 没有新数据就发布全零待机帧
  （画一条待机基线），10s 仍无数据则强杀子进程重连；看门狗时钟 `LastDataMs`。

## 四、Scoop 清单自动刷新

新增 `.github/workflows/scoop.yml`：**每 6 小时**（`0 */6 * * *`）+ 手动触发 +
`release: published` 三种触发方式，跑 `packaging/scoop/update-manifest.sh` ——
从 Releases API 取最新 Windows 包、下载、算 sha256、幂等改写
`packaging/scoop/voicefox.json`，只有真的变了才提交。
不引入第三方 action，`contents: write` 只交给这一份脚本。

同时把仓库里那份**陈旧到 0.3.9** 的清单修正成与最新发布一致
（version / url / hash 三者必须自洽：scoop 安装时校验 sha256，
只改版本号不改 hash 只会让用户装不上）。本版 Windows 包构建完成后，
上面这个工作流会再把它推进到 0.6.0。

## 五、CI 门禁与代码清理

- `ci.yml` 新增 lint job：`cargo fmt --all -- --check` +
  `cargo clippy --workspace --all-targets -- -D warnings`（ubuntu-24.04）。
- 为过门禁做的清理：`let ... &&` 链合并、`SyncOptions { ..Default::default() }`、
  `checked_div` 取代先判零再除、测试模块后的函数归位、
  两处 `#[allow]` 都附上理由注释（`large_enum_variant` / `too_many_arguments`）。

## 六、兼容性与升级

- 配置与数据**无需迁移**：`QrLoginSession` 新增字段带 serde 默认值，
  已有的登录态与扫码会话照常读取。
- 频谱在 Linux 上优先用 `parec`（`pulseaudio-utils` 提供，PipeWire 桌面的
  `pipewire-pulse` 同样提供），拿不到再退回 `pw-record`；
  两者都缺时给出明确提示而不是静默失败。
- QQ 音乐原有的 QQ 扫码入口不变；微信入口是**并列的第二行**，
  不用微信的用户不会被打扰。

## 升级提示

直接替换二进制即可。QQ 音乐用微信注册的账号：设置页（`8`）→「账号与扫码」→
选中 `QQ（微信）` 一行按 `Enter` 扫码；想先确认链路再用真实账号扫码，
可以先跑 `cargo run -p lx-source --example wechat_probe`。
