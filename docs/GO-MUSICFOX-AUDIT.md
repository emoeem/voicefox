# Voicefox × go-musicfox 功能 / 架构审计

> 审计日期：2026-09-18
> 对照对象：`/home/emo/code/go-musicfox` 与 `/home/emo/code/voicefox`
>
> 原则：借鉴成熟设计，不做 Rust 逐文件翻译；Voicefox 保留多音源、JS 音源、下载与本地音乐这条差异化主线。

## 1. 总结

这次逐项代码审计后的结论不是“Voicefox 缺很多功能”。相反，Voicefox 已经吸收了 go-musicfox 最有价值的一批 TUI 能力，并且在多音源、下载和故障切换上更复杂。

当前真正值得继续借鉴的核心只有三类：

1. **播放资源解析层**：已下载文件优先，其次缓存，最后网络；减少重复网络请求。
2. **Track / data manager 思路**：把“歌曲数据获取、缓存、持久化、播放”从页面逻辑中逐步抽离。
3. **成熟的外围体验**：MPRIS、状态栏、快捷键、右键菜单、歌词、缓存管理等继续保持统一入口。

本轮已经实际落地第 1 项：下载记录现在直接参与播放解析，已下载或自动缓存的文件会优先本地播放。

同时补充了下载可靠性与下载中心 UI：非音频 HTTP 响应会在下载阶段被拒绝并触发候选换源，下载页面按进行中 / 等待 / 完成 / 失败组织任务状态，便于定位真实失败原因。

## 3. 可借鉴架构清单

### P0：已经实际采用 / 本轮确认

- **Action Registry**：动作枚举、默认键位、页面 scope、帮助文本统一来源。后续新增操作必须先进入 `Action`，禁止再写孤立快捷键。
- **Context Menu**：歌曲操作以业务 Action 返回，而不是在 UI 菜单内直接修改状态，继续保持这一边界。
- **Playlist Manager**：队列状态集中管理；播放模式通过策略切换；失败计数与自动跳过属于播放域，而不是页面域。
- **Track Manager 思路**：播放前先判断本地资源，再解析网络资源；本轮已将下载记录接入播放路径。

### P1：建议继续演进

- 把 `start_song_playback` 中的“本地 / 缓存 / JS / 内置源”解析进一步抽成独立 `TrackResolver`，让 `main.rs` 只负责 orchestration。
- 给缓存建立独立的生命周期与容量策略。当前 Voicefox 的自动缓存使用下载目录，功能上可用，但长期产品化时应拆成 cache 与 downloads 两个命名空间。
- 统一“请求音质”和“实际音频参数”：Voicefox 已有 `Quality` 与 libmpv `AudioInfo`，下载列表也已经优先展示实测码率。
- 继续保持 `generation + watch + event` 模型，避免快速切歌造成旧请求、旧歌词、旧 mpv 事件污染新歌曲。

### P2：外围集成

- Last.fm scrobble：如果后续增加，放在独立 reporter/service，不污染播放器和音源接口。
- 系统媒体控制：Voicefox 已有 MPRIS；Windows/macOS 若以后需要，再按平台增加 adapter。
- DLNA：单独作为 output backend，不应把网络投送逻辑塞进 SourceManager。

## 4. 不应该引入的功能 / 架构

1. **不要照搬 go-musicfox 的多播放器后端矩阵。** Voicefox 当前 libmpv 已经提供稳定的跨平台音频核心；增加 Beep/MPD/DLNA/系统媒体播放器会扩大测试面，却没有解决当前核心问题。
2. **不要把 Voicefox 重新变成“网易云客户端”。** go-musicfox 的网易云中心模型适合它自身；Voicefox 的核心价值是多平台统一模型。
3. **不要把所有音源暴露成用户必须维护的设置项。** 音源数量是后端基础设施；普通播放应自动选源，只有故障诊断和高级配置才需要进入音源页。
4. **不要因为支持登录就强制登录。** 登录只应该服务于 VIP、个人歌单、受限资源等明确能力。
5. **不要引入 macOS 专属桌面歌词作为主线功能。** 当前项目重点是 Linux TUI + libmpv + 多音源。
6. **不要为了频谱可视化牺牲播放器稳定性。** Spectrum 属于后期视觉增强，不应进入播放主链。
7. **不要把页面 UI 反向耦合到音源实现。** 页面只消费统一模型和 capabilities；平台差异留在 source crate。
8. **不要复制整张队列作为高频切歌数据结构。** Voicefox 已采用 `Arc<Vec<_>>`；继续保持共享快照。
## 5. 实际实现记录

### 已完成：本地优先播放

播放路径现在变为：

`已下载 / 自动缓存文件 → JS 音源 → 对应内置音源 → 自动换源`

下载记录仍以“歌手 - 歌名”作为去重索引，并在文件被删除后自动回收索引。因此已经下载的歌曲再次播放时不需要重新访问网络；自动缓存任务完成后也能直接复用本地文件。

这一步只改变播放资源解析顺序，不改变 SourceManager 的音源协议，也不改变现有下载文件格式。

## 7. 后续工程原则

Voicefox 后续不是“看到 go-musicfox 有什么就加什么”，而是只吸收能够降低复杂度、提高可靠性或改善 TUI 一致性的部分。

**核心顺序：播放可靠性 → 资源解析/缓存 → 下载可靠性 → 数据一致性 → 音源能力 → 系统集成 → 视觉增强。**
