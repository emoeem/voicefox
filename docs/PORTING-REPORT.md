# 移植报告：go-music-dl / music-lib → voicefox

> 本文记录这轮移植的完成度、验证结果与剩余缺口。
> 数据来源于代码本身与联网实测（2026-09-17）。

## 一、移植背景

目标是吸收两个参考项目的能力：

- **go-music-dl**：下载周边能力（下载记录、WebDAV、自动缓存）与浏览侧能力（链接直解、歌单分类、本地音乐）；
- **music-lib**：12 个平台的音源实现（voicefox 原本只有 6 个）。

两者都是 AGPL-3.0，voicefox 是 MIT。移植按其实现思路在 Rust 侧独立实现；本文档所涉改动尚未提交，正式合入时需要决定是否整体切换为 AGPL-3.0。

## 二、已完成的功能

### 1. 地基（接口与模型层）

| 内容 | 说明 |
|---|---|
| `SourceId` 扩展 | 新增 6 个平台（千千/JOOX/5sing/Jamendo/Apple/汽水），显示名集中到 `display_name()` / `display_label()` |
| 能力声明 | 新增 `SourceCapabilities`（歌单/分类/专辑/歌手/榜单/直解/登录/扫码/我的歌单/VIP），界面按能力决定入口显隐 |
| 接口扩展 | `parse_link`（链接直解）、`get_playlist_categories`、`get_user_playlists`、`create_qr_login`/`check_qr_login`、`is_vip_account`、`logout`、`is_logged_in` |
| 模型扩展 | `Playlist` 增加 creator/link/extra；新增 `PlaylistCategory`、`ParsedLink`、`QrLoginSession`/`QrLoginResult` |
| 默认音源集合 | 新增 `SourceId::default_enabled()`，与 `all_online()` 的差异只有 Apple Music（只能试听，默认关闭） |
| 配置迁移 | 版本 1 → 16 的增量迁移：每次新增内置音源只给"没动过音源列表"的用户补上 |

### 2. 下载侧

| 功能 | 实现要点 |
|---|---|
| 下载记录 | `~/.config/voicefox/data/downloads.json`，记录终态（成功/跳过/失败）与相对路径，面板底部显示最近 5 条，`C` 清空 |
| 跨会话去重 | 去重键为「歌手 - 歌名」，**换文件名模板或重启后仍能跳过**；文件被删除后自动回收索引 |
| WebDAV 同步 | PUT + 逐级 MKCOL + Basic Auth；支持粘贴 `https://用户:密码@主机/路径` 自动拆分账号；上传失败只警告 |
| 播放自动缓存 | `auto_cache_on_play`，播放满 N 秒后自动入队；与手动下载共用去重索引与下载面板 |
| 体积与码率 | 解析地址后显示「12.3MB · 320kbps」，引擎探测值优先于音源声明值 |
| 本地文件型音源 | 下载管理器识别"音源给出本地路径"的情况直接复制（汽水解密缓存依赖它） |

## 三、联网验证结果（重要）

离线单测无法发现接口层的问题，因此新增了 `source/tests/network_smoke.rs`（4 个 `#[ignore]` 用例，可手动联网执行）。实测发现并修复：

| 问题 | 根因 | 修复 |
|---|---|---|
| 千千所有接口报 `error decoding response body` | 服务端强制 gzip，且无视 `Accept-Encoding: identity` | 用已有的 `flate2` 按魔数解压 |
| 汽水搜索恒返回 `empty_search` | music-lib 里写死的 Android 设备指纹已失效 | 改用网页端参数（`aid=386088` + `device_platform=web`） |
| Apple Music 找不到 token | 页面 JWT 前缀变化，且共有 3 个不同用途 token | 收集全部候选并逐个探测（用搜索接口探测，避开"曲目不在该区返回 404"的干扰） |
| 酷我歌单搜索解析失败 | 接口返回 JS 对象字面量（裸键 + 单引号） | 加最小改写层再交给 serde |
| 千千链接识别不出 | 域名已迁移到 `91q.com` | 补域名规则 |
| 酷狗取址恒失败 | `/v3/album_audio/audio` 的 `data` 是嵌套数组 `[[{...}]]` | 兼容两种结构 |

同时确认了一项**平台策略变化**：酷狗与千千现在**不给未登录用户返回播放地址**（免费曲目也一样，免登录的移动端与 trackercdn 接口全部返回空 URL）。酷狗已按 music-lib 的 `fetchURLV5` 实现登录态取址（`/v5/url` + 两级签名），未登录时给出明确提示"请在设置页扫码登录"。

**验证方法的一个教训**：第一轮用「周杰伦」测所有音源，因为他的曲目在国内平台几乎全是 VIP，导致误判"酷我/咪咕的播放也坏了"。现在测试支持 `SMOKE_KEYWORD` 覆盖，并且每首会试 3 个曲目。

## 四、尚未完成

### A. 阻塞性问题（影响可用性）

1. **QQ 播放地址**：已完成修复并通过网络 smoke；改用当前 `GetVkey` 请求体并按文件名匹配 `midurlinfo`。
2. **JOOX 播放地址**：`web_get_songinfo` 返回空响应体，接口疑似下线，需要替代来源。
3. **千千播放地址**：`tracklink` 响应里没有 `path`/`url`（同响应带 `isVip`/`isPaid`），需要确认登录态能否解锁；酷狗的 v5 阶梯已写好但**要扫码登录后才能端到端验证**。

### B. 音源能力缺口

4. **歌单分类**：JOOX、Jamendo（两者在 music-lib 里要解析网页内嵌 JSON，且带 base64 标题）、5sing、汽水（平台无此能力）未接入。
5. **我的歌单**：QQ、咪咕、汽水未接入（QQ 需要登录后的额外校验流程）。
6. **专辑曲目**：酷狗/酷我/QQ/网易云/咪咕/B站仍走「搜索后过滤」兜底，应换成各家的专用专辑接口；酷狗的专辑链接明确提示不支持。
7. **VIP 账号识别**：`is_vip_account` trait 已留口，12 个音源都没有实现（music-lib 对网易云/QQ/酷狗/汽水/B站有）。
8. **汽水专辑**：单曲/歌单/歌词/直解已接，专辑未接。
9. **汽水扫码登录**：music-lib 自己也没调通（依赖动态 `a_bogus`/`msToken` 风控签名）。

### C. go-music-dl 侧尚未移植的功能

10. **视频生成（MV 导出）**：浏览器 canvas 渲染帧 + ffmpeg 合成。TUI 场景不适用，是唯一被有意搁置的大功能。
11. **本地音乐作为一等搜索源**：把本地曲库混进搜索结果（go-music-dl 用 SQLite 索引）。
12. **在线歌单/专辑导入为本地自建歌单**。
13. **Cookie 手动填写界面**：现在只能扫码登录；对扫码不稳的平台（汽水）很需要。
14. **专辑搜索模式**：搜索页只有单曲搜索，歌单页有歌单搜索，没有专辑搜索（trait 里也还没有 `search_albums`）。
15. **歌单分类的独立浏览页**：现在是「分类选择器 → 分类下歌单列表」，没有独立的分类页。
16. **更新检查 / GitHub 代理**：桌面分发相关，TUI 无意义。

### D. 工程与交付

17. 已提交并推送：`fbf831f feat(source): expand music sources and download features`。
18. **未在 macOS / Windows 上验证**。
